# 内存监控、释放与三指标菜单栏需求

## 背景

CPUAlert 当前只展示 CPU 与 GPU。新增内存后，菜单栏必须在有限空间里同时保持三项指标可读、稳定且不引起频繁重排；“清理”必须对应真实、可解释且可撤销边界清晰的操作。

## 用户故事

1. 作为普通用户，我希望直接在菜单栏看到 CPU、GPU、内存三项占用，以便无需打开面板判断机器状态。
2. 作为排查卡顿的用户，我希望看到系统内存压力、已用/总内存和高占用进程，以便定位问题。
3. 作为需要快速释放内存的用户，我希望选择不再需要的应用并让它们正常退出，以便尽可能保留应用的保存机会。
4. 作为使用 VoiceOver 的用户，我希望三项指标和释放操作都有完整文字说明，而不是只能理解颜色或图形。

## 功能需求

### FR-1 系统内存

- 采集物理内存总量、可回收口径下的已用量、压缩内存和使用比例。
- 使用 Apple 公共 Mach API；采集失败时显示不可用，不沿用伪造值。
- 已用量采用 `active + wired + compressed` 的压力相关口径，并限制在物理内存总量内；inactive/cache 不算入压力占用。
- 内存压力级别沿用当前统一阈值分级，但与 CPU/GPU 独立保留迟滞状态。

### FR-2 进程内存

- 在现有 PID 扫描中读取 `ri_phys_footprint`，不增加第三次全进程扫描。
- 内存榜按物理占用降序排列，最多保留 20 项、界面按设置显示 5 或 10 项。
- 展示应用/进程名称、PID、物理占用；进程身份继续使用 PID + 启动时间防止 PID 复用。

### FR-3 释放内存

- 内存页提供“释放内存…”入口。
- 弹窗只列出当前用户、普通 GUI 应用且不属于保护策略的候选项。
- 默认不勾选任何应用；用户显式选择并二次确认后才执行。
- 批量释放只发起优雅退出，不自动升级为强制终止。
- 显示预计涉及的物理占用，并注明实际释放量会因共享页、压缩和应用行为不同而变化。
- 逐项反馈成功、仍在运行、身份已变化、受保护或失败；不得调用私有 API、`purge` 或不透明缓存清理命令。

### FR-4 三指标菜单栏

- 固定宽度展示 C/G/M 三个等宽单元，避免数值变化造成菜单栏跳动。
- 每个单元包含单字母标签、无百分号的 0–100 数字和独立压力色条。
- GPU 不可用时展示短横线；其他指标采集失败时保留最近一次有效值，但可访问性文字必须说明当前不可用。
- VoiceOver 标签完整朗读 CPU、GPU、内存的百分比与压力状态。

### FR-5 主面板

- 顶部同时展示 CPU、GPU、内存摘要。
- 趋势图同时绘制三条曲线，并提供不依赖颜色的图例。
- 资源切换新增“内存”，显示内存榜与释放入口。
- 内存数值使用二进制容量格式（GiB/MiB）。

### FR-6 性能与稳定性

- 系统内存采样不阻塞主线程。
- 进程内存排行复用现有进程扫描与应用元数据缓存。
- 菜单栏保持固定尺寸，不因 1/2/3 位数字重新布局。
- 现有 CPU、GPU 采样、GPU 卡片整卡展开、设置和退出行为不得回归。

## 非功能需求

- macOS 15+、Apple Silicon，Swift 6 严格并发可编译。
- 所有破坏性操作均需明确用户动作和确认。
- 所有新增控件具备可访问性标签与稳定 UI 测试标识。
- 发布前通过单元测试、UI 测试、静态分析、Release 构建和签名验证。

## 非目标

- 不宣称能够清空系统缓存或保证释放指定字节数。
- 不实现自动杀进程、定时杀进程或无确认强制退出。
- 不读取私有 Activity Monitor 接口，也不安装新的特权组件。

## 验收标准

1. 运行时可见 C/G/M 三联菜单栏，数字对齐稳定，GPU 不可用仍正常布局。
2. 内存页能显示真实系统容量和按物理占用排序的进程。
3. 释放弹窗默认零选择，只有明确选择并确认才会退出应用。
4. 保护进程、CPUAlert 自身和非普通应用不进入批量候选。
5. 内存采集失败不会崩溃或显示虚假的 0%。
6. 自动化测试覆盖内存计算、排行、候选过滤、采样集成、菜单栏格式和 UI 主流程。
